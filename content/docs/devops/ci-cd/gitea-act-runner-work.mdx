## 🔄 单个Runner执行流程

```
┌─────────────────────────────────────────────────────────────────┐
│                        Act Runner Process                        │
│                                                                  │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │  1. 启动 Runner                                             │ │
│  │     ./act_runner register --instance <gitea-url>            │ │
│  │     ./act_runner daemon                                     │ │
│  └──────────────────────┬─────────────────────────────────────┘ │
│                         │                                        │
│                         ▼                                        │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │  2. 轮询 Gitea Server (每 2 秒)                             │ │
│  │     GET /api/v1/runners/{runner_id}/jobs                    │ │
│  └──────────────────────┬─────────────────────────────────────┘ │
│                         │                                        │
│                         ▼                                        │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │  3. 接收到 Job                                              │ │
│  │     - 下载 workflow 文件                                    | |
|  |	 - 检查 labels 是否匹配                                   │ │
│  │     - 根据标签映射找到对应的 Docker 镜像                       │ │
│  │     - 检查本地是否存在该镜像,                                 │  │
│  │         存在 → 直接使用本地镜像                               │  │
│  │         不存在 → 从远程仓库拉取                               │  │  
│  │     - 解析 steps                                            │ │
│  └──────────────────────┬─────────────────────────────────────┘ │
│                         │                                        │
│                         ▼                                        │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │  4. 启动 Docker 容器                                         │ │
│  │     docker run -v /workspace:/workspace \                   │ │
│  │                --name act-job-{id} \                        │ │
│  │                catthehacker/ubuntu:act-latest               │ │
│  └──────────────────────┬─────────────────────────────────────┘ │
│                         │                                        │
│                         ▼                                        │
└─────────────────────────┼──────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────────┐
│                      Docker Container                            │
│                     (临时执行环境)                                │
│                                                                  │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │  5. 执行 Steps (串行)                                        │ │
│  │                                                             │ │
│  │  Step 1: Checkout                                           │ │
│  │  ┌───────────────────────────────────────┐                 │ │
│  │  │ git clone <repo> /workspace           │                 │ │
│  │  └───────────────────────────────────────┘                 │ │
│  │                    │                                        │ │
│  │                    ▼                                        │ │
│  │  Step 2: Setup Environment                                  │ │
│  │  ┌───────────────────────────────────────┐                 │ │
│  │  │ export ENV_VAR=value                  │                 │ │
│  │  │ source .bashrc                        │                 │ │
│  │  └───────────────────────────────────────┘                 │ │
│  │                    │                                        │ │
│  │                    ▼                                        │ │
│  │  Step 3: Run Commands                                       │ │
│  │  ┌───────────────────────────────────────┐                 │ │
│  │  │ npm install                           │                 │ │
│  │  │ npm test                              │                 │ │
│  │  │ npm build                             │                 │ │
│  │  └───────────────────────────────────────┘                 │ │
│  │                    │                                        │ │
│  │                    ▼                                        │ │
│  │  Step 4: Upload Artifacts (可选)                            │ │
│  │  ┌───────────────────────────────────────┐                 │ │
│  │  │ tar -czf artifacts.tar.gz dist/       │                 │ │
│  │  │ upload to Gitea                       │                 │ │
│  │  └───────────────────────────────────────┘                 │ │
│  │                                                             │ │
│  └──────────────────────┬──────────────────────────────────────┘ │
│                         │                                        │
│                         ▼                                        │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │  6. 收集结果                                                 │ │
│  │     - stdout/stderr 日志                                    │ │
│  │     - exit code (成功/失败)                                  │ │
│  │     - artifacts (可选)                                      │ │
│  └──────────────────────┬─────────────────────────────────────┘ │
│                         │                                        │
└─────────────────────────┼──────────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────────┐
│                    回到 Runner Process                           │
│                                                                  │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │  7. 上报结果到 Gitea Server                                  │ │
│  │     POST /api/v1/runners/{runner_id}/jobs/{job_id}/status  │ │
│  │     - 实时流式上传日志                                        │ │
│  │     - 更新 Job 状态 (running → success/failure)             │ │
│  │     - 上传 artifacts                                        │ │
│  └──────────────────────┬─────────────────────────────────────┘ │
│                         │                                        │
│                         ▼                                        │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │  8. 清理容器 🗑️                                              │ │
│  │     docker stop act-job-{id}                                │ │
│  │     docker rm act-job-{id}                                  │ │
│  │                                                             │ │
│  │     清理内容:                                                │ │
│  │     ✓ 删除容器实例                                           │ │
│  │     ✓ 释放容器占用的资源                                      │ │
│  │     ✓ 清理临时文件 (除非配置保留)                             │ │
│  │     ✗ 保留 workspace 缓存 (可选)                             │ │
│  │     ✗ 保留 artifacts (已上传)                                │ │
│  └──────────────────────┬─────────────────────────────────────┘ │
│                         │                                        │
│                         ▼                                        │
│  ┌────────────────────────────────────────────────────────────┐ │
│  │  9. 回到等待状态                                             │ │
│  │     继续轮询下一个任务...                                     │ │
│  └────────────────────────────────────────────────────────────┘ │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

## 🔄 容器生命周期
```
┌──────────────────────────────────────────────────────────────┐
│                      容器生命周期                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  创建 → 运行 → 完成 → 销毁                                    │
│   ↓      ↓      ↓      ↓                                    │
│  docker docker  Job   docker                                │
│  run    exec   Done   rm                                    │
│                                                              │
│  时间线:                                                      │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━    │
│  │      │               │          │                        │
│  0s    1s             30s-300s    +2s                       │
│  创建   启动           执行中      清理                        │
│                                                              │
│  保留的内容:                                                  │
│  ┌─────────────────────────────────────┐                    │
│  │ ✓ Gitea 服务器上的日志                │                    │
│  │ ✓ 上传的 artifacts                   │                    │
│  │ ✓ workspace 缓存 (可配置)             │                    │
│  │ ✗ 容器文件系统                        │                    │
│  │ ✗ 容器进程和网络                      │                    │
│  └─────────────────────────────────────┘                    │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 💡 资源优化机制
```
┌──────────────────────────────────────────────────────────────┐
│                    为什么要销毁容器?                           │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  1. 资源释放                                                  │
│     • 释放 CPU、内存、磁盘空间                                 │
│     • 防止资源泄漏                                            │
│                                                              │
│  2. 环境隔离                                                  │
│     • 每个 Job 都是全新环境                                   │
│     • 避免上一个 Job 的副作用                                 │
│                                                              │
│  3. 安全性                                                    │
│     • 不保留敏感信息                                          │
│     • 清除运行时凭证                                          │
│                                                              │
│  4. 并发能力                                                  │
│     Job 1:  [容器] → 销毁                                    │
│     Job 2:         [容器] → 销毁                             │
│     Job 3:                [容器] → 销毁                      │
│                                                              │
│     如果不销毁:                                               │
│     Job 1:  [容器────────────────────────] (资源占用)        │
│     Job 2:         [容器─────────────────] (资源占用)        │
│     Job 3:                [容器──────────] (资源占用)        │
│     → 很快耗尽资源!                                           │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 🏷️ Labels 匹配机制

```
Workflow 文件:                    Runner 配置:
┌─────────────────┐              ┌─────────────────┐
│ runs-on:        │              │ labels:         │
│   - ubuntu-22.04│    匹配?     │  - ubuntu-22.04 │
│   - docker      │ ◄──────────► │  - docker       │
└─────────────────┘      ✓       │  - linux        │
                                 └─────────────────┘

匹配规则:
1. Workflow 的所有 labels 必须在 Runner labels 中存在
2. 支持多 labels 组合 (AND 关系)
3. Runner 可以有额外的 labels (超集)   
```

## 💾 存储结构

```
/opt/act_runner/
├── .runner              # Runner 配置文件
├── .runner_token        # 认证 Token
├── data/
│   ├── cache/          # 缓存目录
│   ├── logs/           # 本地日志
│   └── workspace/      # 工作空间
│       └── {org}-{repo}-{job_id}/
│           ├── _actions/     # Actions 缓存
│           ├── _temp/        # 临时文件
│           └── {repo}/       # 仓库代码
└── docker_volumes/     # Docker 挂载卷
```

## ⚡ 关键特性

```
┌──────────────────────────────────────────────────────────┐
│  1. 并发执行                                              │
│     ┌────────┐  ┌────────┐  ┌────────┐                  │
│     │ Job 1  │  │ Job 2  │  │ Job 3  │                  │
│     └────────┘  └────────┘  └────────┘                  │
│     同时运行在不同容器中                                   │
│                                                          │
│  2. 容器隔离                                              │
│     每个 Job 独立的 Docker 容器                           │
│     互不影响,执行完自动清理                                │
│                                                          │
│  3. 增量执行                                              │
│     支持 cache 机制                                       │
│     依赖缓存、构建缓存                                     │
│                                                          │
│  4. 失败重试                                              │
│     支持 Job 级别重试                                     │
│     可配置重试次数和间隔                                   │
└──────────────────────────────────────────────────────────┘
```
