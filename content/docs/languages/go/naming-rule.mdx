## 1. 核心原则

### 1.1 可见性规则

Go 通过**首字母大小写**控制可见性：

```go
// 大写开头 = 导出（Public）
type UserService interface {}
func NewUser() {}
const MaxConnections = 100

// 小写开头 = 未导出（Private）
type userService struct {}
func validateEmail() {}
const defaultTimeout = 30
```

**官方说明：**
> The first character of a name determines its visibility: if it begins with an upper-case letter, it is exported.

## 2. 包命名（Package Names）

### 规则
- ✅ 全小写，无下划线
- ✅ 简短、清晰、有意义
- ✅ 单数形式（除非标准库已使用复数）
- ❌ 避免泛化命名如 `util`、`common`

### 示例

```go
// ✅ 推荐
package user
package http
package json

// ❌ 不推荐
package User          // 不要大写
package user_service  // 不要下划线
package utils         // 太泛化
```

### 导入使用

```go
import (
    "net/http"           // 标准库
    "myapp/internal/user" // 本地包
)

// 使用时：包名.标识符
http.Get()
user.NewService()
```

**官方文档**: https://go.dev/doc/effective_go#package-names

## 3. 接口命名（Interface Names）

### 规则
- ✅ 单方法接口：方法名 + `er` 后缀
- ✅ 多方法接口：描述性名词
- ✅ 首字母大写（导出）

### 示例

```go
// ✅ 单方法接口
type Reader interface {
    Read(p []byte) (n int, err error)
}

type Writer interface {
    Write(p []byte) (n int, err error)
}

type Closer interface {
    Close() error
}

// ✅ 多方法接口
type UserRepository interface {
    Create(user *User) error
    FindByID(id int) (*User, error)
    Update(user *User) error
    Delete(id int) error
}

// ✅ 组合接口
type ReadWriteCloser interface {
    Reader
    Writer
    Closer
}
```

**官方说明：**
> By convention, one-method interfaces are named by the method name plus an -er suffix.

## 4. 结构体命名（Struct Names）

### 4.1 导出结构体

```go
// ✅ 公开的配置、DTO、实体
type User struct {
    ID       int
    Username string
    Email    string
}

type Config struct {
    Port     int
    Host     string
    Timeout  time.Duration
}
```

### 4.2 未导出结构体（实现细节）

```go
// ✅ 接口的私有实现
type UserRepository interface {
    Create(user *User) error
}

type userRepository struct {  // 小写，隐藏实现
    db *gorm.DB
}

func NewUserRepository(db *gorm.DB) UserRepository {
    return &userRepository{db: db}
}
```

### 4.3 命名模式对比

```go
// 模式1：接口 + 私有实现（推荐）
type FileRepository interface {}
type fileRepository struct {}

// 模式2：具体结构体（用于简单场景）
type Config struct {}
type User struct {}
```

## 5. 函数/方法命名（Function/Method Names）

### 5.1 构造函数

```go
// ✅ New 前缀
func New() *Service {}              // 包内唯一服务
func NewUser() *UserService {}      // 多个服务时明确类型
func NewWithConfig(cfg Config) {}   // 带配置
```

### 5.2 Getter 不使用 Get 前缀

```go
type User struct {
    name string  // 私有字段
}

// ✅ 推荐：直接用字段名
func (u *User) Name() string {
    return u.name
}

// ❌ 不推荐
func (u *User) GetName() string {
    return u.name
}
```

**官方说明：**
> Go doesn't provide automatic support for getters and setters. If you have a field called owner, the getter method should be called Owner, not GetOwner.

### 5.3 Setter 使用 Set 前缀

```go
// ✅ Setter 可以用 Set
func (u *User) SetName(name string) {
    u.name = name
}
```

### 5.4 布尔方法命名

```go
// ✅ Is/Has/Can/Should 前缀
func (u *User) IsActive() bool {}
func (u *User) HasPermission(perm string) bool {}
func (u *User) CanEdit() bool {}
```

## 6. 变量命名（Variable Names）

### 6.1 局部变量：简短

```go
// ✅ 短作用域用短名字
for i := 0; i < 10; i++ {}
if err != nil {}

var (
    u  *User        // 单字母（作用域很小）
    db *gorm.DB
    r  *http.Request
)
```

### 6.2 全局变量/常量：描述性

```go
// ✅ 全局变量要清晰
var (
    ErrNotFound = errors.New("not found")
    DefaultTimeout = 30 * time.Second
)

// ✅ 常量组
const (
    StatusPending  = "pending"
    StatusApproved = "approved"
    StatusRejected = "rejected"
)
```

### 6.3 驼峰命名

```go
// ✅ 驼峰（CamelCase）
var userName string
var maxRetryCount int

// ❌ 不要用下划线
var user_name string
var max_retry_count int
```

## 7. 常量命名（Constant Names）

### 7.1 常规常量

```go
// ✅ 驼峰命名
const MaxConnections = 100
const defaultTimeout = 30

// ❌ 不要用全大写（这不是 C/Java）
const MAX_CONNECTIONS = 100
```

### 7.2 枚举常量

```go
// ✅ 使用 iota
type Status int

const (
    StatusPending Status = iota
    StatusApproved
    StatusRejected
)

// ✅ 字符串枚举
const (
    RoleAdmin  = "admin"
    RoleUser   = "user"
    RoleGuest  = "guest"
)
```

## 8. 错误命名（Error Names）

### 规则
- 错误变量：`Err` 前缀
- 错误类型：`Error` 后缀

```go
// ✅ 错误变量
var (
    ErrNotFound     = errors.New("not found")
    ErrUnauthorized = errors.New("unauthorized")
    ErrInvalidInput = errors.New("invalid input")
)

// ✅ 自定义错误类型
type ValidationError struct {
    Field   string
    Message string
}

func (e *ValidationError) Error() string {
    return fmt.Sprintf("%s: %s", e.Field, e.Message)
}
```

**官方文档**: https://go.dev/blog/error-handling-and-go

## 9. 缩写规则（Acronyms）

### 保持一致的大小写

```go
// ✅ 缩写全大写或全小写
type UserAPI struct {}
var userAPI *UserAPI

type HTTPServer struct {}
var httpServer *HTTPServer

// ❌ 不一致
type UserApi struct {}   // 应该是 UserAPI
type HttpServer struct {} // 应该是 HTTPServer
```

常见缩写：
- `API` 不是 `Api`
- `HTTP` 不是 `Http`
- `ID` 不是 `Id`
- `URL` 不是 `Url`
- `JSON` 不是 `Json`

**官方说明**: https://go.dev/wiki/CodeReviewComments#initialisms

## 10. 实战示例

### 示例 1：Repository 层

```go
package repository

import "gorm.io/gorm"

// 类型别名
type User = model.User

// 导出接口
type UserRepository interface {
    Create(user *User) error
    FindByID(id uint) (*User, error)
    FindByEmail(email string) (*User, error)
    Update(user *User) error
    Delete(id uint) error
}

// 私有实现
type userRepository struct {
    db *gorm.DB
}

// 构造函数
func NewUser(db *gorm.DB) UserRepository {
    return &userRepository{db: db}
}

// 方法实现
func (r *userRepository) FindByID(id uint) (*User, error) {
    var user User
    err := r.db.First(&user, id).Error
    return &user, err
}
```

### 示例 2：Service 层

```go
package service

import "myapp/internal/repository"

type UserService interface {
    Register(username, email, password string) error
    Login(email, password string) (string, error)
    GetProfile(userID uint) (*User, error)
}

type userService struct {
    repo  repository.UserRepository
    cache Cache
}

func NewUser(repo repository.UserRepository, cache Cache) UserService {
    return &userService{
        repo:  repo,
        cache: cache,
    }
}

func (s *userService) GetProfile(userID uint) (*User, error) {
    // 先查缓存
    if cached, ok := s.cache.Get(userID); ok {
        return cached.(*User), nil
    }
    
    // 查数据库
    user, err := s.repo.FindByID(userID)
    if err != nil {
        return nil, err
    }
    
    // 写缓存
    s.cache.Set(userID, user)
    return user, nil
}
```

### 示例 3：HTTP Handler

```go
package handler

import "github.com/gin-gonic/gin"

type UserHandler struct {
    service service.UserService
}

func NewUser(service service.UserService) *UserHandler {
    return &UserHandler{service: service}
}

// 注册路由

    users := r.Group("/users")

        users.POST("/register", h.Register)
        users.POST("/login", h.Login)
        users.GET("/:id", h.GetProfile)
    }
}
```

## 11. 命名检查清单

使用前检查：

- [ ] 包名全小写，无下划线？
- [ ] 导出的标识符首字母大写？
- [ ] 私有实现首字母小写？
- [ ] 接口命名符合 `-er` 规则？
- [ ] Getter 没有 `Get` 前缀？
- [ ] 变量名长度与作用域匹配？
- [ ] 缩写大小写保持一致？
- [ ] 错误变量使用 `Err` 前缀？
- [ ] 没有使用下划线命名？

## 12. 常见错误对比

| ❌ 错误写法 | ✅ 正确写法 | 说明 |
|-----------|-----------|------|
| `type UserApi struct` | `type UserAPI struct` | 缩写全大写 |
| `func GetName()` | `func Name()` | Getter 不用 Get |
| `var user_name string` | `var userName string` | 用驼峰不用下划线 |
| `package Utils` | `package util` | 包名小写 |
| `const MAX_SIZE = 100` | `const MaxSize = 100` | 常量用驼峰 |
| `type userrepository` | `type userRepository` | 驼峰命名 |
| `ErrNotfound` | `ErrNotFound` | 每个单词首字母大写 |

## 总结

Go 的命名哲学：
1. **简洁而非简短** - 短但要有意义
2. **一致性优先** - 跟随标准库风格
3. **可读性第一** - 名字要能自解释
4. **大小写传达意图** - 公开/私有一目了然
