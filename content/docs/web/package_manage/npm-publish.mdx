# npm 发包流程

这篇文档面向需要把组件库、工具库或 CLI 发布到 npm 的场景，重点整理发布前准备、登录、发布和常见错误处理。

## 发布前准备

至少确认下面几项：

- `package.json` 中的 `name` 没有重名
- `version` 合法
- `private` 不是 `true`
- `files`、`main`、`module`、`types` 配置正确

一个最小示例：

```json
{
  "name": "my-lib",
  "version": "1.0.0",
  "private": false,
  "main": "./dist/index.cjs",
  "module": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "files": ["dist"]
}
```

## 登录 npm

先确保 registry 是官方源：

```bash
npm config set registry https://registry.npmjs.org/
```

然后登录：

```bash
npm login
```

如果你的 npm 版本较新，也可能走浏览器授权流程。

## 发布命令

```bash
npm publish
```

如果是作用域包且希望公开发布：

```bash
npm publish --access public
```

## 发布前建议执行的检查

```bash
npm pack
```

这个命令会先生成一个本地 tarball，你可以快速确认最终会被发布哪些文件。

## 如何控制发包内容

优先使用 `files` 字段：

```json
{
  "files": ["dist", "README.md"]
}
```

如果需要排除额外文件，也可以使用 `.npmignore`。

## 常见问题

### 1. 发布时命中了镜像源

如果你使用了国内镜像，`npm login` 或 `npm publish` 可能失败。先切回官方源：

```bash
npm config set registry https://registry.npmjs.org/
```

发布完成后如果有需要，再切回镜像源。

### 2. 包名已存在

说明 `name` 已被占用，需要更换一个未被注册的名称。

### 3. 版本已发布

同一个版本号不能重复发布，需要更新 `version`：

```bash
npm version patch
```

## 撤销发布

撤销整个包通常要非常谨慎：

```bash
npm unpublish my-lib --force
```

撤销某个版本：

```bash
npm unpublish my-lib@1.0.1
```

注意 npm 对撤销发布有时间和策略限制，生产环境不建议依赖这种方式回滚。

## 实用建议

- 发布前先跑测试和构建
- 用 `npm pack` 检查发包内容
- 给库补齐 README、types 和 changelog
- 不要把源码目录、测试目录、截图等无关文件一起发上去
