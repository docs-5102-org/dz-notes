# MySQL UPDATE LOW_PRIORITY 详解

## 概述

`LOW_PRIORITY` 是 MySQL 中用于降低语句执行优先级的关键字,可以防止更新操作长时间锁定表,从而提高读取操作的响应速度。

### 基本语法

```sql
UPDATE [LOW_PRIORITY] tbl_name 
SET col_name1=expr1, col_name2=expr2, ...
WHERE condition;
```

## MySQL 默认调度策略

MySQL 采用以下默认调度策略来协调多客户端的并发访问:

1. **写入优先于读取** - 写入操作(DELETE、INSERT、REPLACE、UPDATE)优先级高于读取操作(SELECT)
2. **写入互斥** - 对同一张表的写入操作同一时刻只能发生一次,按到达顺序依次处理
3. **读取并发** - 对同一张表可以同时进行多个读取操作

### 锁机制说明

**写锁(排他锁)**
- 写入操作需要获取独占访问权
- 防止数据在修改过程中被其他客户端读取或修改
- 确保数据和索引的一致性

**读锁(共享锁)**
- 读取操作获取的锁不需要独占访问
- 允许多个客户端同时读取同一张表
- 防止读取过程中数据被修改

> **注意**: 此调度策略主要适用于 MyISAM 和 MEMORY 存储引擎(使用表级锁)

## LOW_PRIORITY 的作用

### 正常情况下的执行顺序

```
时间线: 读取1 → 写入(等待) → 读取2(被阻塞) → 写入执行 → 读取2执行
```

- 读取1 正在执行时,写入操作到达,等待读取1 完成
- 读取2 到达时被阻塞,因为写入操作优先级更高
- 读取1 完成后,写入操作执行,读取2 继续等待

### 使用 LOW_PRIORITY 后的执行顺序

```
时间线: 读取1 → 写入(低优先级等待) → 读取2(插队执行) → 读取2完成 → 写入执行
```

- 写入操作标记为低优先级后,不再优先于读取操作
- 新到达的读取操作可以插队到写入操作之前
- 只有在没有读取操作时,写入操作才会执行

### 潜在风险

⚠️ **饥饿问题**: 如果读取请求持续不断到达,LOW_PRIORITY 写入操作可能永远无法执行

## 语句调节符总览

MySQL 提供以下调节符来修改默认调度策略:

| 调节符 | 适用语句 | 适用引擎 | 作用 |
|--------|---------|---------|------|
| LOW_PRIORITY | DELETE, INSERT, LOAD DATA, REPLACE, UPDATE | MyISAM, MEMORY | 降低写入优先级 |
| HIGH_PRIORITY | SELECT, INSERT | MyISAM, MEMORY | 提高读取优先级 |
| DELAYED | INSERT, REPLACE | MyISAM, MEMORY | 延迟插入 |

## 使用场景与建议

### 适用场景

- 读多写少的应用场景
- 对写入实时性要求不高的业务
- 需要确保查询响应速度的系统

### 更优的替代方案

在生产环境中,有更好的方式来平衡读写性能:

1. **主从复制** - 读写分离,主库写入,从库读取
2. **缓存层** - 使用 Redis、Memcached 等缓存减轻数据库压力
3. **InnoDB 引擎** - 使用行级锁,提高并发性能
4. **分库分表** - 分散数据库压力

## 全局配置

如果希望所有支持的语句默认使用低优先级,可以在启动 MySQL 时使用:

```bash
mysqld --low-priority-updates
```

在此配置下,可以使用 `HIGH_PRIORITY` 关键字来提升单个语句的优先级:

```sql
INSERT HIGH_PRIORITY INTO table_name VALUES (...);
```

## 总结

- `LOW_PRIORITY` 可以防止写入操作长时间阻塞读取操作
- 适用于读密集型应用,但要警惕写入饥饿问题
- 现代应用更推荐使用主从复制、缓存等架构方案
- 考虑使用 InnoDB 引擎以获得更好的并发性能
