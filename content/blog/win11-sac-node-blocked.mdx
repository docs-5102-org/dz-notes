# Windows 11 Smart App Control 拦截 `.node` 原生模块问题处理

> 适用场景：pnpm / npm 安装原生 Node.js Addon（`.node` 文件）时报错
> `fatal - Error: An Application Control policy has blocked this file.`

---

## 问题背景

`.node` 文件是 Native Node.js Addon（本质是 DLL），Windows 安全策略对**未签名或来源不明的二进制文件**会触发 Application Control 拦截。

Windows 11 存在两套拦截机制：

| 机制 | 说明 | 可否针对单文件关闭 |
|---|---|---|
| **Windows Defender** | 传统防病毒，可加排除目录 | ✅ 可以 |
| **Smart App Control (SAC)** | Win11 22H2+ 新增，更激进 | ❌ 只能整体关闭 |

---

## 快速诊断：判断是哪种机制在拦截

### 检查 SAC 状态

以管理员身份打开 PowerShell，执行：

```powershell
Get-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy" `
  -Name "VerifiedAndReputablePolicyState" 2>$null
```

**返回值含义：**

| 值 | 含义 |
|---|---|
| `1` | SAC **开启**中（拦截根源） |
| `0` | SAC 关闭 / 评估模式 |

### 查看事件日志（可选，精确定位）

```powershell
Get-WinEvent -LogName "Microsoft-Windows-CodeIntegrity/Operational" -MaxEvents 10 |
  Where-Object { $_.Message -like "*pack.win32*" } |
  Select-Object TimeCreated, Message
```

---

## 解决方案

### ✅ 方案一：关闭 SAC（推荐，一劳永逸）

**路径：** Windows 安全中心 → 应用和浏览器控制 → Smart App Control → **关闭**

> ⚠️ **注意：** SAC 一旦关闭**无法重新开启**（系统级限制，需重装系统才能恢复）。
> 开发机完全可以接受，生产机勿操作。

---

### 方案二：通过注册表切换评估模式（需重启）

不想通过 UI 操作，也可用 PowerShell（管理员）直接修改注册表：

```powershell
# 切换为评估模式（不拦截但会记录）
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy" `
  -Name "VerifiedAndReputablePolicyState" -Value 0 -Type DWord

# 重启生效
Restart-Computer
```

---

### 方案三：从 Windows Defender 隔离区恢复文件（临时处理）

适用于文件已被隔离、需要快速恢复的情况：

1. 打开 **Windows 安全中心** → 病毒和威胁防护
2. 点击 **保护历史记录**
3. 找到对应 `.node` 文件的隔离记录
4. 点击 **允许** / **还原**

---

### 方案四：添加 Defender 排除目录（补充措施）

关闭 SAC 后，建议同步添加开发目录到 Defender 排除项，避免后续继续触发：

```powershell
# 排除整个开发工作区
Add-MpPreference -ExclusionPath "E:\dev_workspace"

# 或仅排除 .node 扩展名
Add-MpPreference -ExclusionExtension ".node"

# 验证排除项
Get-MpPreference | Select-Object -ExpandProperty ExclusionPath
```

---

## 处理完成后：重新安装依赖

```powershell
# 删除问题 node_modules
Remove-Item -Recurse -Force .\node_modules

# 清理 pnpm store 缓存（可选）
pnpm store prune

# 重新安装
pnpm install
```

---

## 推荐操作顺序

```
1. 执行诊断命令，确认 SAC 状态
       ↓
2. VerifiedAndReputablePolicyState = 1
       ↓
3. Windows 安全中心关闭 SAC（方案一）
       ↓
4. 添加 Defender 排除目录（方案四）
       ↓
5. 重新 pnpm install
```

---

## 备注

- 本问题在 **pnpm + 原生 Addon** 场景下尤为常见，涉及包如 `@utoo/pack-win32-x64-msvc`、`better-sqlite3`、`sharp`、`canvas` 等
- SAC 是 Win11 22H2（2022年10月）引入的新特性，升级系统后首次遇到此类问题的开发者较多
- 开发环境建议统一关闭 SAC，减少不必要的干扰
